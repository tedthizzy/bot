# Pi-side orchestrator (Python on Linux), 2026 practice

Research date: 2026-09-07. Versions below were read from PyPI/GitHub/apt metadata on that date unless stated otherwise.

## Summary

- Process model: one asyncio "brain" process plus two thin systemd sidecars (`rover-io` serial/safety bridge, `rover-cam` picamera2 frame server), joined by pyzmq 27 over `ipc://` sockets with `CONFLATE` for latest-value topics. This is the pattern LeRobot's LeKiwi host already uses (ZMQ PULL/PUSH, CONFLATE, JPEG multipart, 500 ms watchdog, 30 Hz loop), so the LeKiwi merge path stays straight. A single monolith is acceptable for the desk gate; split before the chassis gate.
- OS: Raspberry Pi OS Trixie 64-bit Lite (released 2025-10-02, Python 3.13.5, kernel 6.12 at release and 6.18.39 in the archive today, `python3-picamera2 0.3.37-1` via apt). Do not install Ubuntu 24.04 "for ROS 2": ROS 2 Lyrical Luth (May 2026, LTS) targets Ubuntu 26.04 Tier 1 and lists Ubuntu 24.04 and Debian Trixie as Tier 3. Do not run the voice/serial/camera processes in Docker on the Pi.
- The brief's voice stack is partly stale. `wyoming-satellite` was deprecated on 2026-01-27 in favour of OHF-Voice `linux-voice-assistant` (asyncio, Python >=3.11, `pymicro-wakeword`/`pyopen-wakeword`). Vosk's last release is 0.3.50 (2024-04-22; PyPI 0.3.45 from 2022). `sherpa-onnx` 1.13.7 (2026-09-01) is the maintained on-device streaming ASR with cp313 aarch64 wheels. `piper-tts` 1.8.0 (2026-09-04) streams `AudioChunk`s by sentence.
- Latency hiding that works in 2026: sentence-streamed TTS (Home Assistant measured >5 s to ~0.5 s first audio), pre-rolled filler audio, a text-only first pass for non-visual intents chosen by a deterministic router on the Pi, and relying on vLLM's prefix caching, which is on by default in vLLM V1 (`enable_prefix_caching: bool = True`).
- ROS 2 correction: Zenoh is Tier 1 since Kilted (May 2025) but is not the default in Lyrical; the default remains `rmw_fastrtps_cpp`. Mirror `geometry_msgs/TwistStamped` (Nav2 defaults `enable_stamped_cmd_vel=true` since Kilted) and `nav_msgs/Odometry` in your JSON, and defer ROS 2 itself to the box.

## State of the art (2026)

### Voice satellite software on a Pi
The Home Assistant/OHF stack is the reference for a Python voice loop on a Pi, and it changed in the last 12 months:
- `wyoming-satellite` README: "This project is no longer maintained as it has been replaced by Linux Voice Assistant that uses the ESPHome protocol" (2026-01-27). Its `arecord`/`aplay` subprocess pipeline is the old pattern.
- `linux-voice-assistant` v1.1.15 (2026-08-02): one asyncio process, Python >=3.11 (tested 3.11 and 3.13), `pymicro-wakeword>=2,<3` and `pyopen-wakeword>=1,<2`, `webrtc-noise-gain`, `python-mpv` playback, ESPHome API on port 6053, a "stop" wake-word model for barge-in, `--listen-during-wake-sound`. Deployable via Docker Compose or bare-metal systemd; runs on Pi Zero 2 W and up.
- The Wyoming protocol itself is alive (`wyoming` 1.10.2, 2026-08-27) and gained streaming events (`transcript-chunk`, `synthesize-chunk`, `synthesize-start/stop`), which is how HA streams TTS by sentence.
- Wake word: PyPI `openwakeword` 0.6.0 dates from 2024-02-11; OHF publishes `pyopen-wakeword` 1.1.0 (2025-10-28) and `pymicro-wakeword` 2.4.1 (2026-06-22). Upstream claims 15-20 openWakeWord models in real time on one Pi 3 core at 80 ms frames.
- STT: Vosk is frozen (GitHub v0.3.50, 2024-04-22; PyPI 0.3.45, 2022-12). Its default Kaldi endpointing is `rule2.min-trailing-silence=0.5`, `rule3=1.0`, `rule4=2.0` s; `KaldiRecognizer.SetEndpointerDelays()` and `SetEndpointerMode()` tune it. `sherpa-onnx` 1.13.7 (2026-09-01) ships streaming Zipformer (an English 20M model labelled "suitable for Cortex A7"), VAD and keyword spotting, lists Raspberry Pi as a platform, and publishes cp310-cp314 aarch64 wheels. `moonshine-voice` 0.1.5 (2026-08-24) targets Pi too; no ARM latency numbers found.
- TTS: `piper-tts` 1.8.0 (`OHF-Voice/piper1-gpl`, GPLv3). `PiperVoice.load()`, then `for chunk in voice.synthesize(text)` yields `AudioChunk(sample_rate, sample_width, sample_channels, audio_int16_bytes)`. HA measured Piper first audio dropping from "more than five seconds" to "about half a second" once responses were chunked at sentence boundaries (HA 2025.7, Piper add-on 1.6.0).

### Process model and IPC
- LeRobot LeKiwi host (lerobot v0.6.1, 2026-08-03): ZMQ PULL command socket on tcp 5555 with `CONFLATE`, PUSH observation socket on 5556 with send HWM 2, JSON actions, multipart observations (JSON header + raw JPEG q90, "avoids the 33% base64 inflation"), `watchdog_timeout_ms=500` calling `robot.stop_base()`, `max_loop_freq_hz=30`.
- `pyzmq` 27.2.0 (2026-08-20). `eclipse-zenoh` 1.10.0 (2026-08-14, abi3 aarch64 wheel) defaults to `mode: "peer"` with multicast scouting on `224.0.0.224:7446`, so peers on one host need no router. rmw_zenoh disables multicast scouting and requires `rmw_zenohd`.
- ROS 2 Lyrical Luth (May 2026, LTS to 2031) adds `AsyncNode`, which "runs an asyncio event loop" and "uses significantly less CPU compared to the default SingleThreadedExecutor". It wants Ubuntu 26.04 (Tier 1) or a source build on Trixie (Tier 3), Python 3.12-3.14.

### Libraries (PyPI, 2026-09-07)
Python 3.13.5 (Trixie default); uv 0.12.10 (aarch64 is Astral Tier 2); picamera2 0.3.37 (apt `python3-picamera2 0.3.37-1`, `python3-libcamera 0.7.2+rpt20260817`; README recommends apt over pip); pyserial-asyncio-fast 0.16 (HA blocks `pyserial-asyncio` from 2026.7 because it "blocks the event loop because it does a blocking sleep"; import `serial_asyncio_fast`); sounddevice 0.5.6; websockets 17.1 (Python >=3.11); openai 3.8.0 (v3.0.0 on 2026-08-12 made HTTPX2 the default client, uses the OS trust store, and stopped installing `httpx`); httpx2 2.12.0; pydantic 2.13.5; python-statemachine 3.2.1 (3.0.0 on 2026-02-24 unified a `StateChart` base with an automatic async engine; in async code you must `await activate_initial_state()`); transitions 0.9.3 (2025-07-02, `AsyncMachine`, no mixing of sync and async callbacks); structlog 26.1.0 (OpenTelemetry structlog instrumentation landed in opentelemetry-python-contrib 1.44.0/0.65b0, 2026-07); vllm 0.28.0 on the box (`guided_*` deprecated since 0.12.0 in favour of `structured_outputs`).

### OS, containers, read-only root
- Raspberry Pi OS Trixie: released 2025-10-02; 64-bit Lite available; "We do not recommend or support attempting to upgrade a running Bookworm image." A libpisp/libcamera break on 2025-10-09 was fixed via apt the next day; hold apt upgrades before demos.
- Docker on Pi (arXiv 2505.02082, Pi 3B+, May 2025): 0.56% CPU latency overhead, up to 1.3% memory overhead, bridge networking 10.1 ms vs 2.5 ms host mode with ~14% throughput loss, "1-10 ms latency penalty per I/O operation" to peripherals, 100-500 ms cold starts. CPU is not the problem; device passthrough, bridge latency and RAM on a 4 GB board are.
- Read-only root: Trixie's raspi-config (20260730) `enable_overlayfs` installs Debian's `overlayroot` package and prepends `overlayroot=tmpfs` to cmdline; Bookworm used a custom initramfs. raspi-config issue #288 (2025-10-25, open) and bookworm-feedback #137/#207 report the default `recurse=1` making every partition read-only; the forum workaround is `overlayroot="tmpfs:recurse=0"` in `/etc/overlayroot.local.conf` plus a separate rw data partition.
- CPU pinning: systemd `CPUAffinity=` per unit or `AllowedCPUs=` on a slice; `isolcpus=3` only if you need a quiet core. A Pi 3B+ measurement with `isolcpus` + `SCHED_FIFO` + raised `sched_rt_runtime_us` got <3 us typical and 41 us worst-case at 1 kHz over 18 h; without the RT budget change the author saw 50 ms stalls once per second. A 300 ms TTL needs none of this.

### Structured output on the box
- vLLM 0.28 accepts `response_format={"type":"json_schema", ...}` or `extra_body={"structured_outputs": {"json": schema}}`; backends `xgrammar`, `guidance`, `outlines`, default `auto`. `enable_prefix_caching` defaults to `True` in `vllm/config/cache.py`.
- Gemma 3 27B: vLLM issue #21148 (2025-07-17) reports the server hanging after a couple of tokens with JSON structured output on xgrammar from v0.9.0; closed as stale, not fixed. Issue #15403 asks for JSON-based tool calling for Gemma 3. Test `--structured-outputs-config.backend guidance` before trusting either.
- `client.chat.completions.parse(response_format=YourPydanticModel)` in openai 3.x does the schema plumbing and returns `.parsed`; keep your own `model_validate` plus bounds/TTL checks, because the grammar guarantees shape only.

### Latency hiding in voice agents
Pipecat defaults TTS to `TextAggregationMode.SENTENCE`: "when the first sentence boundary lands, that sentence is fired to TTS, so the user hears the first word before the LLM has finished." Its 2026 latency guide claims 200-500 ms from streaming partial LLM tokens to TTS, 200-400 ms from prefix caching, 80-200 ms from audio prebuffering plus a TTS "opener", and 50-150 ms from a long-lived TTS session. These are cloud-service claims; the mechanisms transfer, the numbers do not.

## Recommendation for this build

### Processes and supervision
Three systemd units, each `Restart=always`, `RestartSec=1`, `WatchdogSec=10` with `sd_notify` pings from the event loop:
1. `rover-io` (asyncio, `pyserial-asyncio-fast`, `pyzmq`): owns `/dev/ttyACM0`, sends the ESP32 heartbeat at 10 Hz, forwards validated commands, publishes odometry/ToF/bumper/battery telemetry on `ipc:///run/rover/telemetry` (PUB, `CONFLATE` on the subscriber), accepts commands on `ipc:///run/rover/cmd` (PULL). Only this process writes to the serial port. Keep it under 300 lines, no ML imports, `CPUAffinity=3`, `Nice=-5`. If `rover-brain` dies, `rover-io` stops sending motion and the ESP32 TTL stops the wheels within 300 ms regardless.
2. `rover-cam` (picamera2, system Python): 640x480 at 10 fps into a 2 s ring, publishes JPEG (hardware encoder) with a header `{"ts": ..., "seq": ..., "exposure_ms": ...}` on `ipc:///run/rover/frame` (PUB, `CONFLATE`). `rover-brain` takes the newest frame at end-of-speech and records `observation_age_ms`. Separate process because libcamera stalls are the most common hang on Pi cameras and picamera2 must import from apt's Python.
3. `rover-brain` (asyncio): wake word, VAD, STT, state machine, LLM client, validator, TTS, scene memory, debug HTTP page. Everything else is a safety or isolation boundary.

Use pyzmq, not Zenoh, for v1: the LeKiwi merge you named uses ZMQ with the same patterns, and raw zenoh-python cannot talk to rmw_zenoh nodes without ROS key expressions and CDR anyway.

### Environment
- Raspberry Pi OS Trixie 64-bit Lite. `sudo apt install python3-picamera2 --no-install-recommends`. Create the venv from the system interpreter so apt's `python3-libcamera` bindings import: `uv venv --python /usr/bin/python3 --system-site-packages .venv`, then `uv pip install ...`. Do not let uv download python-build-standalone 3.13 for the camera process.
- Pin: `openai>=3,<4`, `pydantic>=2.13,<3`, `pyserial-asyncio-fast>=0.16`, `pyzmq>=27`, `sounddevice>=0.5.6`, `piper-tts>=1.8`, `sherpa-onnx>=1.13` (or `vosk==0.3.45` if you keep Vosk), `pymicro-wakeword>=2,<3` or `pyopen-wakeword>=1,<2`, `structlog>=26`.
- Overlay root only at gate 4, using `overlayroot="tmpfs:recurse=0"` and a rw `/data` partition for scene memory, logs and model caches.

### State machine
Hand-roll it. Six states as a `StrEnum` (`IDLE, LISTENING, THINKING, ACTING, SPEAKING, ERROR`), one `asyncio.Queue` of typed events (pydantic models), one coroutine per state, and `asyncio.timeout()` on every wait. Barge-in is a cancellation: the wake-word task always runs; on detection it puts `Wake` on the queue, and the state coroutine that is awaiting (TTS playback, LLM stream, or action completion) is cancelled, `stop()` is sent to `rover-io`, and the machine re-enters `LISTENING`. python-statemachine 3.2 is acceptable if you want diagrams and guards (remember `await sm.activate_initial_state()`); skip transitions.

What `ACTING` waits on: (a) the MCU ack echoing `seq` within 100 ms, else retry once then `ERROR`; (b) a `done{seq, odom}` or `abort{reason}` telemetry event, with deadline `expected_duration * 1.5 + 0.5 s` derived from the validated distance/speed; (c) any bumper/ToF stop event, which wins. The ESP32 executes bounded primitives (`drive(d, v)`, `turn(deg, w)`) on its own encoder loop; the Pi only heartbeats and can pre-empt with `stop`. Keep the brief's 300 ms TTL; LeKiwi uses 500 ms for the same purpose.

### World-state JSON sent to the model (target <300 tokens)
```json
{"ts": 1757260800.12, "mode": "idle",
 "pose": {"frame_id": "odom", "x": 1.42, "y": -0.30, "yaw_deg": 87.0},
 "twist": {"linear_x": 0.0, "angular_z": 0.0},
 "ranges_m": {"front_left": 1.20, "front_right": 0.85}, "bumper": false,
 "battery_v": 11.6, "wifi_rssi": -61,
 "camera": {"frame_ts": 1757260799.98, "age_ms": 140, "attached": true},
 "recent": [{"ts": 1757260790.0, "skill": "turn", "args": {"deg": 60}, "result": "done"}],
 "seen": [{"label": "red mug", "bearing_deg": -20, "ts": 1757260700.0, "confidence": "model"}],
 "person": {"heard_from_deg": null}}
```
Field names mirror `nav_msgs/Odometry` (`pose`, `twist`, `frame_id`, `header.stamp` = `ts`) and `geometry_msgs/TwistStamped` so a later ROS 2 bridge is a rename, not a redesign. Scene memory is a JSON Lines file in `/data/scene.jsonl`, last 20 observations, each `{ts, pose, labels[], frame_path}`; the model receives only the last 5 `seen` entries with ages.

### Skill semantics
One JSON object per turn: `{"speech": "...", "skill": "turn", "args": {"deg": 60}, "needs_image": false}`. Put `speech` first in the schema `properties` so with grammar-constrained decoding its characters arrive first; the Pi runs an incremental scanner on the token stream (after `"speech": "` until the unescaped closing quote) and feeds sentence boundaries to Piper while the skill fields are still generating. This is how you get sentence-streamed TTS out of a JSON-only model.

`find(object)`: bounded loop, at most 6 iterations of `turn(60)` -> capture -> a reduced-schema call whose only allowed outputs are `found{bearing_deg}`, `not_found`, `turn{deg}`; 60 s total budget; every iteration revalidated; barge-in aborts. Never let the model chain skills inside one turn.

### Latency plan (target 1-2 s perceived)
1. End-of-speech from VAD, not from the STT final: set Vosk `SetEndpointerDelays(t_start_max=5.0, t_end=0.35, t_max=8.0)` or the sherpa-onnx endpoint rules so the final text lands ~0.35 s after silence instead of 0.5-1.0 s with defaults.
2. Router before the model: regex/keyword classifier on the transcript for the closed skill set. `drive/turn/stop/say/set_face` never attach an image; `describe_scene/find/what is/where` do; unknown -> text-only first with `needs_image` in the schema, and a second call with the frame only if the model asks. Cost: one extra round trip on ambiguous requests instead of 0.5-1 s image prefill on every turn.
3. Filler: 10-20 pre-synthesized Piper WAVs ("let me look", "one moment") chosen by intent class, started at end-of-speech, cancelled if the first `speech` sentence is ready within 600 ms.
4. Warm path: one long-lived `AsyncOpenAI` client (HTTPX2 pool), a 30-token warm-up request at boot and every 5 min so the system prompt + schema prefix stays in vLLM's cache and the TCP/TLS session stays open. Images are never cache hits; keep them last in the message.
5. Piper `low` or `x_low` English voice on the Pi 4 unless you measure `medium` at RTF <0.7; play the first `AudioChunk` as soon as it arrives.

### Observability
structlog 26 JSON to journald with a `turn_id` bound at wake and these timestamps: `t_wake, t_eos, t_stt_final, t_router, t_llm_first_token, t_llm_done, t_valid, t_mcu_ack, t_action_done, t_tts_first_audio`, plus `observation_age_ms`, `image_attached`, `schema_retry`, `mcu_reject_reason`. Read from the couch with `journalctl -u rover-brain -o json -f` over SSH (Tailscale or plain LAN). Add `prometheus-client` 0.26 counters/histograms on `:9100/metrics` and a 40-line aiohttp debug page showing the last frame, last world-state JSON and last model output. OpenTelemetry is available for structlog but is more than this needs.

## Corrections to the brief

1. "Wyoming" as the satellite framework: `wyoming-satellite` is deprecated (2026-01-27). Borrow the event model from `linux-voice-assistant` (asyncio, stop word, listen-during-wake-sound) instead. The Wyoming protocol is still fine for talking to STT/TTS services on the box.
2. "Vosk small-English streaming ~1 core, final text ~0.3 s after end of speech": Vosk is unmaintained since 2024-04 and its default endpointing waits 0.5 s of trailing silence, so 0.3 s only holds after `SetEndpointerDelays`. The only Pi measurement I found is RTF 1.5 on a Pi 3 B; a Pi 4 is roughly 2x faster per core, so ~1 core for real time is plausible but unverified. sherpa-onnx streaming Zipformer is the maintained choice; measure both on your mic.
3. "openWakeWord ~5-10% of a core": holds. Upstream's Pi 3 claim implies 5-7% per model on a Pi 3 core; Pi 4 will be lower. Use `pyopen-wakeword`/`pymicro-wakeword`, not `openwakeword` 0.6.0.
4. "Piper low/medium near real time [INFERRED]": no 2025-2026 Pi 4 measurement found. Blogs steer Pi 4 users to `low`/`x_low`. The bigger win is sentence streaming, which HA measured at 10x faster first audio.
5. "Enable prefix caching on the box": already on by default in vLLM V1 (0.28). Nothing to enable; verify it was not disabled, and note images never hit the cache.
6. "Assume Gemma-class: don't rely on native tool-call parsing": correct, and stronger than stated. vLLM #21148 reports Gemma 3 27B hanging under xgrammar structured output from v0.9.0 (closed unfixed). Test `guidance` as the backend and keep the pydantic reject-and-retry.
7. "Zenoh/rmw_zenoh as 2026 default": wrong. Lyrical Luth's default is `rmw_fastrtps_cpp`; `rmw_zenoh_cpp` is Tier 1 (since Kilted) but opt-in via `RMW_IMPLEMENTATION=rmw_zenoh_cpp` and needs `rmw_zenohd`.
8. "Ubuntu 24.04 for future ROS 2": Jazzy (EOL 2029) is the only LTS on 24.04; Lyrical wants 26.04. Choosing the Pi OS today for a ROS 2 install two years out is premature; run ROS 2 on the box or in a container when the time comes.
9. "Message shapes mirroring geometry_msgs/Twist": mirror `TwistStamped` (header + twist). Nav2 publishes TwistStamped by default since Kilted.
10. `pyserial-asyncio`: use `pyserial-asyncio-fast` 0.16; HA blocks the old package from 2026.7 for blocking the event loop.
11. "openai SDK with response_format json_schema": openai 3.x still supports it, but v3.0.0 moved to HTTPX2 and stopped installing `httpx`; pin a major and read `httpx2.md` if you use custom transports.
12. "Python 3.12/3.13": Trixie ships 3.13.5; everything you need has cp313 or pure wheels except picamera2, which must come from apt and therefore from the system interpreter.
13. "Docker on Pi 4 overhead": CPU overhead is under 1%, but the measured bridge-network and peripheral I/O penalties and 4 GB RAM argue against containers for audio/serial/camera on this board.
14. "640x480 JPEG at 10 fps ~20-40% of a core": unverified; picamera2 can use the hardware JPEG encoder, so it may be lower. Measure at gate 3.

## Alternatives considered and rejected

- One process for everything: fine for the desk gate, but a libcamera hang or a segfault in an ONNX runtime takes the safety heartbeat down with it. Rejected for the chassis.
- One process per library (audio, wake, STT, TTS, brain) over ZMQ: crash isolation you do not need and 4-5 extra Python interpreters on 4 GB. Rejected.
- Threads instead of asyncio: sounddevice/Piper/sherpa are blocking C calls; wrap them in `asyncio.to_thread` inside one loop rather than hand-managing threads.
- Zenoh (`eclipse-zenoh`) as the Pi IPC: attractive because rmw_zenoh is Tier 1, but raw Zenoh is not wire-compatible with rmw_zenoh without ROS key expressions and CDR, LeRobot uses ZMQ, and Fast DDS is still the ROS default. Revisit if you move the brain into a ROS 2 `AsyncNode`.
- python-statemachine / transitions: acceptable, not necessary; six states and cancellation-based barge-in are clearer hand-rolled.
- Pipecat or LiveKit Agents on the Pi: designed around cloud STT/TTS WebSockets; heavy for a Pi 4 and their latency numbers are cloud numbers.
- Home Assistant + linux-voice-assistant as the orchestrator: would put HA in the control path; the robot's brain is not a smart-home pipeline. Borrow the code patterns only.
- Tiny LLM intent classifier on the Pi (Qwen 0.5B class via llama.cpp): no verified Pi 4 numbers found within this research; a regex/keyword router covers a closed skill set deterministically.
- Docker Compose on the Pi (as linux-voice-assistant offers): see Docker numbers; bare-metal systemd is the documented alternative.
- Ubuntu 24.04 Server on the Pi: 3x idle RAM of Pi OS Lite by blog measurements, Tier 3 for Lyrical; no benefit for v1.
- Read-only root on day one: Trixie's overlayroot behaviour is still changing (raspi-config #288 open); enable at gate 4 with `recurse=0`.

### Stale or missing

- **Corrections aimed at a different document.** brief.md contains no mention of Wyoming, Zenoh, rmw_zenoh, Ubuntu 24.04, `geometry_msgs/Twist`, `pyserial-asyncio`, the openai SDK, Python 3.12/3.13, or Docker. "Corrections to the brief" #1, #7, #8, #9, #10, #11, #12 and #13 therefore correct claims the brief never makes. Only #2 (Vosk 0.3 s), #3 (openWakeWord 5-10%), #4 (Piper), #5 (prefix caching), #6 (Gemma tool calls) and #14 (JPEG 20-40%) map to brief text.
- **vLLM is assumed, the brief does not say so.** The brief calls the box "dumb" and specifies only "an OpenAI-compatible endpoint" whose extra hosting is "negotiable but not assumed". The note's prefix-caching correction, `--structured-outputs-config.backend guidance`, `extra_body={"structured_outputs": ...}` and issue #21148 all presuppose vLLM. If the box runs llama.cpp/Ollama/SGLang/TGI the brief's "enable prefix caching" is still an action item and the vLLM-specific advice is moot. Asking the box operator to change the structured-output backend is itself a negotiation the brief flags.
- **`guided_*` were removed, not deprecated, in vLLM 0.12.0** per `docs/features/structured_outputs.md`.
- **"Images are never cache hits" is wrong as stated.** vLLM hashes multi-modal inputs into block hashes; an identical image is a hit. Distinct camera frames miss, which is the practical point.
- **`AsyncNode` is `rclpy.experimental`** in Lyrical; the note presents it as a settled feature.
- **Wyoming streaming events date.** `transcript-chunk`/`synthesize-chunk` streaming landed in `wyoming` 1.7.0 (2025-06-23), not in the 1.10.x line the note cites.
- **Dates off by small amounts.** wyoming-satellite deprecation commit 2026-01-08 (not 01-27); Vosk issue #331 is 2020-12-24 (not 2021); Trixie image 2025-10-01 (announcement 10-02).
- **Docker I/O penalty attributed to the wrong board.** The 1-10 ms per-I/O figure was measured on a Pi 4; the rest on a Pi 3B+. None of it is a Pi 4 + kernel 6.18 measurement.
- **RT forum numbers are from December 2018** (Pi 3B+, Raspbian Stretch, kernel 4.14). Mainline 6.12+ carries PREEMPT_RT; the note should say the numbers are eight years old.
- **"Hardware JPEG encoder" needs the right class.** picamera2's `JpegEncoder` is software (`simplejpeg`, 4 threads); the hardware path is `MJPEGEncoder` (V4L2 M2M, raises "Hardware MJPEG not available on this platform" on Pi 5). `capture_file()`/still capture uses the software path. Name `MJPEGEncoder` in `rover-cam` or the 20-40% CPU estimate stands.
- **Pipecat quote is not on the cited page.** docs.pipecat.ai says only that the default is `TextAggregationMode.SENTENCE` and that `TOKEN` mode lowers latency; the "when the first sentence boundary lands..." sentence is a paraphrase.
- **Unverified low-quality sources kept as "VENDOR".** zbotic.in RAM/boot numbers and the localaimaster Piper blog were not corroborated; treat as anecdote.
- **Missing: acoustic echo cancellation for barge-in.** The design runs the wake-word/stop-word detector during Piper playback with the speaker 0.3-1 m from the mic. `linux-voice-assistant` uses `webrtc-noise-gain` (no AEC). A 2026 practitioner would either use a mic array with hardware AEC (ReSpeaker XVF3800 / Satellite1 style) or mute/duck the mic during playback and accept no barge-in.
- **Missing: stable serial device path.** `/dev/ttyACM0` is enumeration-order dependent once a USB mic and camera are present; use a udev rule or `/dev/serial/by-id/...` in `rover-io`.
- **Missing: hardware watchdog.** Per-unit `WatchdogSec=` restarts a hung Python process but not a frozen kernel or a stalled SD card; set `RuntimeWatchdogSec=` in `/etc/systemd/system.conf` (bcm2835_wdt) so the Pi reboots and the ESP32 TTL remains the only thing that stops the wheels.
- **Missing: Wi-Fi power save.** brcmfmac power save on the Pi 4 adds 100-300 ms latency spikes; `iw dev wlan0 set power_save off` (persisted via a systemd unit or NetworkManager `wifi.powersave 2`) belongs in the desk gate before measuring turn latency or the Wi-Fi-cut stop gate.
- **Missing: audio server decision on Trixie Lite.** Trixie desktop defaults to PipeWire; Lite has bare ALSA. `sounddevice`/PortAudio talks ALSA; `linux-voice-assistant`'s docs assume PipeWire. Pick one and pin the device by ALSA card name, or the wake word and Piper will fight over the device.
- **Missing: memory budget.** No RSS figures for sherpa-onnx (streaming Zipformer + VAD), Piper (`medium` ~60 MB model), wake word, three CPython interpreters and a 2 s JPEG ring on a 4 GB board; the brief's headroom claim rests on CPU only.
- **Missing: clock discipline.** World-state `ts`/`frame_ts`/`age_ms` compare Pi, box and MCU clocks; install `chrony` on Pi and box and time-stamp MCU telemetry on receipt.
- **Missing: retry cost in the latency plan.** A pydantic reject-and-retry adds a full 1.5-2.5 s generation; the 600 ms filler cancel window and the 1-2 s perceived target do not account for it.
- **Stale by design, flagged by the note but worth repeating:** `openwakeword` 0.6.0 (2024-02) and `vosk` 0.3.45 (2022-12) wheels; vLLM's user-facing APC doc still reads as opt-in while the code default is on.
